# Round 4 findings

## High
- The stale pre-deploy writer remains able to overwrite newer sales or voids, print and confirm a void as chargeable, or recreate a whole old snapshot before the new page's one-sided `storage` handler can block anything; BUILD verification on the intended PWA does not fence an already-open Safari context. (Persist a monotonic revision and minimum-writer schema in `ij.v1`, require every mutation to compare-and-fail-closed against freshly loaded state, fence obsolete builds from writing or confirming, and test two-context old/new interleavings for sale, batch, void, and confirm.)
- The service worker still deletes N-1 immediately after N merely precaches successfully, so a syntactically complete but behaviorally broken N becomes the only offline shell and can wedge the counter precisely when the network is unavailable; this does not satisfy the prior round's known-good rollback requirement. (Retain a bounded N-1 cache until N passes the installed-iPad acceptance gate, add an operator-triggered/promoted active cache or equivalent rollback path, and rehearse upgrade and rollback while both online and offline before enabling the worker for the trial.)

## Medium
- E0 labels every commit revertable but verifies only forward smoke tests and never exercises a rollback with v2 typed, voided, pending, and processed data, so incompatibility in the claimed reader floor would be discovered only during an incident. (Pin and display the rollback-floor commit, document which revisions are forbidden, and make a deploy gate that writes representative v2 state, rolls the iPad back to the floor, verifies totals/status/reprints and continued sales, then rolls forward without clearing that state.)
- Creating a batch makes the only loss-window alert disappear even if AirPrint failed or no sheet reached the tray, while the plan's rejection of an operator attestation leaves no Pending-batch age, last verified copy, named escalation, or kiosk-visible overdue signal. (Add an explicit human-confirmed "copy in tray" timestamp per Pending batch, alert on both old unbatched sales and unverified/overdue Pending batches on the kiosk and in admin, and define the checkpoint owner, retry/escalation steps, and stop-selling threshold in the runbook.)
- Capacity safety is deferred until an unmeasured 40% threshold based on guessed traffic and a character-count proxy, with no iPad quota test, quota-headroom alert, or large-batch render/print soak, so storage or report size can still halt purchases mid-trial without a recovery procedure. (Measure actual iPad storage headroom and real sales volume before trial, soak localStorage plus View/Print at conservative peak and 30-day volumes, set tested warn/stop thresholds, and specify an export-verified prune procedure for processed history before enabling automatic pruning.)
